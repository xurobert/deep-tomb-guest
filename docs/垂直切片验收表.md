# 垂直切片验收表

本文档为《深墓来客》垂直切片（Vertical Slice, VS）验收标准，用于在大规模编码与美术制作前确认核心体验可行性。

---

## 锁定的设计决策

| 项目 | 决策 |
|------|------|
| 视角 | 2.5D 俯视箱庭 + 立绘对话（非 3D） |
| 内容分级 | 16+，暗色内容做柔化处理 |
| 版权 | 纯同人 / 个人使用（仅取氛围；原创角色设计；无官方肖像） |
| 类型 | 纯回合制箱庭 RPG（无棋盘战斗） |
| 引擎 | Godot 4 |
| 美术 | 瓦片 32×32，角色精灵 64×64，Filter/Mipmaps OFF |
| 命名规范 | `subject_state_dir_frame`（如 `hero_idle_s_00.png`） |
| 显示术语 | 异能共鸣 / 失控 / 认可（代码 id 可保留英文） |

---

## 1. 垂直切片范围

### 包含（In Scope）

- 单一探索房间（含地面、墙壁、可交互物）
- 玩家角色移动与碰撞
- 一个存档点（魂灯）功能
- 一次 1v1 回合制战斗（对战 Tomb Shade）
- 一个技能「异能共鸣」（Deep Echo）
- 失控槽 UI 显示
- 战后「认可」Toast 提示
- 基础 HUD（HP、认可点）

### 不包含（Out of Scope）

- 多房间 / 场景切换
- 道具 / 装备系统
- 多敌人 / Boss 战
- 完整对话系统 / 剧情演出
- 音频（BGM / SE）
- 游戏结束画面 / 重生逻辑
- 最终美术资源（当前使用占位色块）

## 2. 如何在 Godot 4 中运行

### 环境准备

1. 安装 [Godot 4.2+](https://godotengine.org/download)
2. 克隆本仓库

### 打开项目

1. 启动 Godot 4
2. 点击「导入」（Import）
3. 选择仓库根目录下的 `project.godot`
4. 点击「导入并编辑」

### 运行游戏

- 按 **F5** 启动
- 或点击编辑器右上角的「播放」按钮

### 操作说明

| 动作 | 按键 |
|------|------|
| 移动 | WASD / 方向键 |
| 交互 | E / 空格 |
| 确认 | Enter / Z |
| 取消 | Esc / X |

## 3. 验收清单

> 测试者逐项确认并勾选。全部通过方可视为 VS 验收合格。

### 功能验收

- [ ] **探索房间**：玩家可在房间内自由移动，与墙壁正确碰撞
- [ ] **交互提示**：靠近可交互物时显示交互提示（黄色=文物，红色=敌人，蓝色=存档点）
- [ ] **存档点**：与魂灯交互后成功保存，重启游戏可读档
- [ ] **回合制战斗 1v1**：与敌人交互进入战斗，战斗流程完整（玩家回合→敌人回合循环）
- [ ] **异能共鸣**：战斗中可使用「异能共鸣」技能，造成伤害
- [ ] **失控槽显示**：使用技能后，失控槽 UI 可见且数值增加
- [ ] **认可 Toast**：击败敌人后显示「认可」获取提示
- [ ] **无崩溃**：完整流程无引擎报错或崩溃

### 通过标准

- 全部 8 项勾选 ✅ → VS 功能验收通过
- 任意项未通过 → 记录问题，修复后重测

## 4. 体验评估（定性）

> 由测试者主观判断核心体验是否达成。用于评估设计方向，非硬性通过条件。

| 体验目标 | 描述 | 是否感受到 |
|----------|------|------------|
| **越界压迫** | 探索时感受到未知与危险的压迫感 | ☐ 是 / ☐ 否 |
| **异能翻盘** | 战斗中使用「异能共鸣」时有逆转战局的爽快感 | ☐ 是 / ☐ 否 |
| **被注视感** | 整体氛围营造出"有什么在暗处注视着你"的感觉 | ☐ 是 / ☐ 否 |

### 备注

- 三项中至少两项「是」视为体验方向正确
- 若多数为「否」，需重新审视核心设计或演出手法

## 5. 当前脚手架的已知限制

| 限制 | 说明 |
|------|------|
| 占位美术 | 角色与物件使用彩色方块，无精灵动画 |
| 单一房间 | 无场景切换，仅一个测试房间 |
| 单一敌人 | 仅 Tomb Shade 一种敌人 |
| 单一技能 | 仅「异能共鸣」可用 |
| 无音频 | BGM / SE 未实装 |
| 无游戏结束 | HP 归零后需手动重启 |
| 战斗 UI | 全屏覆盖式，无空间感战斗画面 |

## 6. 完成定义（Definition of Done）

在进入大规模编码与美术制作前，必须满足以下条件：

### 必须满足

- [ ] **验收清单全部通过**：第 3 节的 8 项功能验收全部勾选
- [ ] **体验方向确认**：第 4 节体验评估至少 2/3 为「是」
- [ ] **核心循环可运行**：探索 → 交互 → 战斗 → 成长（认可）循环完整
- [ ] **技术稳定**：连续运行 10 分钟无崩溃或内存泄漏

### 建议满足

- [ ] **团队内部评审通过**：至少 2 人完成完整测试并签字
- [ ] **已知问题记录**：所有发现的 bug 已记录到 issue tracker
- [ ] **美术规范确认**：占位色块可无缝替换为最终资源（尺寸、锚点正确）
