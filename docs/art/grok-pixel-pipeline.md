# Grok 像素资产生成管线

> 状态：**已锁定**  
> 锁定日期：2026-09-10

本文档定义使用 Grok 生成像素美术资产的标准化工作流程，确保所有生成图经过正确处理后方可进入游戏资产目录。

---

## 管线概览

```
Grok 生成原图
     ↓
正方形中心裁切
     ↓
最近邻缩放至目标尺寸
  ├── 精灵 (map-sprite): 32×32 px
  └── 瓦片 (map-tile): 16×16 px
     ↓
量化至锁定 8 色板
     ↓
人工审核（原尺寸 + 8 倍最近邻放大）
     ↓
  ├── ✅ 通过 → assets/ 按命名规范存放
  └── ❌ 未通过/概念图 → docs/art/ref/ 标注「非进仓」
```

## 步骤详解

### 第 1 步：Grok 生成原图

使用 Grok 图像生成功能创建参考图，建议提示词包含：

- 像素美术风格描述
- 角色/物件基本特征
- 俯视/正交视角指令
- 简洁背景（便于后续裁切）

**注意**：Grok 生成的高清图（如 1280×720）为原始素材，**不可直接用于游戏**。

### 第 2 步：正方形中心裁切

从生成图中心裁切出正方形区域：

1. 确定主体在画面中的位置
2. 以主体为中心裁切正方形
3. 确保重要细节不被裁切掉

### 第 3 步：最近邻缩放

使用**最近邻插值（Nearest Neighbor）**缩放至目标尺寸：

| 资源类型 | 目标尺寸 |
|----------|----------|
| 地图精灵 (map-sprite) | 32×32 px |
| 地图瓦片 (map-tile) | 16×16 px |

**⚠️ 禁止**：使用双线性（Bilinear）、双三次（Bicubic）或任何抗锯齿插值算法。

### 第 4 步：量化至 8 色板

将缩放后的图像颜色量化至锁定的 8 色调色板：

1. 打开像素编辑器（Aseprite / Pixelorama / Photoshop）
2. 导入锁定色板
3. 使用索引色模式或手动替换颜色
4. 确保最终图像仅包含 8 色板中的颜色

### 第 5 步：人工审核

审核时需查看两种视图：

| 视图 | 缩放 | 用途 |
|------|------|------|
| 原尺寸 | 1× (32×32 或 16×16) | 确认游戏中实际显示效果 |
| 放大视图 | 8× 最近邻放大 | 检查像素细节、轮廓、色彩分布 |

#### 审核检查清单

- [ ] 主体轮廓清晰可辨
- [ ] 色彩仅使用锁定 8 色
- [ ] 无模糊/抗锯齿残留
- [ ] 锚点位置正确（角色脚底居中）
- [ ] 适合目标用途（精灵/瓦片）

## 输出路径与命名

### ✅ 审核通过：进入 assets/

通过审核的最终像素资产存放于 `assets/` 目录，按标准命名规范：

```
assets/art/
├── characters/   # 角色精灵
│   └── <subject>_<state>_<dir>_<frame>.png
└── tiles/        # 地图瓦片
    └── <subject>_<variant>.png
```

**命名格式**：`<主体>_<状态>_<方向>_<帧号>.png`

示例：
- `hero_idle_s_00.png` — 主角待机，朝南，第 0 帧
- `enemy_bone_guard_attack_e_01.png` — 骨卫攻击，朝东，第 1 帧
- `tile_floor_stone_00.png` — 石砖地面变体 0

详细命名规范见 [naming-and-import.md](naming-and-import.md)。

### ❌ 审核未通过或概念参考：存入 docs/art/ref/

未通过审核的处理稿、概念图、或高清原图仅作参考，存放于：

```
docs/art/ref/
├── grok/         # Grok 生成的原图/参考图
├── concept/      # 概念草图
└── processed/    # 处理中间稿（未通过审核）
```

**必须标注**：文件名或文档引用处注明「**非进仓**」。

示例：
- `hero_concept_ref_非进仓.png`
- `bone_guard_grok_v1_非进仓.png`

## 🚫 禁止事项

### 绝对禁止

| 禁止项 | 原因 |
|--------|------|
| 将 1280×720 等高清图直接导入 SpriteFrames | 破坏像素美术风格，文件体积过大 |
| 使用双线性/双三次插值缩放游戏帧 | 产生模糊，破坏像素锐利边缘 |
| 任何抗锯齿处理后的图作为游戏资产 | 与 8 色板冲突，像素不纯净 |
| 未量化至 8 色的图像进入 assets/ | 色彩不统一，视觉风格不一致 |
| 概念图/未通过审核图进入 assets/ | 需标注「非进仓」存于 docs/art/ref/ |

### Godot 导入设置检查

所有像素资产导入时必须确认：

| 设置项 | 正确值 |
|--------|--------|
| Filter | **OFF** (Nearest) |
| Mipmaps | **OFF** |
| Compress | **Lossless** |

## 工具建议

### 图像处理

| 工具 | 用途 |
|------|------|
| Aseprite | 像素编辑、色板管理、动画帧制作 |
| Pixelorama | 免费像素编辑器，支持索引色 |
| ImageMagick | 命令行批量裁切/缩放 |
| GIMP | 通用图像处理 |

### ImageMagick 命令示例

```bash
# 最近邻缩放至 32x32
convert input.png -filter Point -resize 32x32 output.png

# 中心裁切正方形
convert input.png -gravity Center -crop 512x512+0+0 +repage cropped.png

# 组合：裁切 + 缩放
convert input.png -gravity Center -crop 512x512+0+0 +repage \
        -filter Point -resize 32x32 output.png
```

## 工作流示例

### 示例：创建主角待机帧

1. **Grok 生成**：提示词生成主角站立姿态参考图
2. **裁切**：从 1280×720 中心裁切 720×720 正方形
3. **缩放**：最近邻缩放至 32×32
4. **量化**：在 Aseprite 中转换为锁定 8 色板
5. **审核**：
   - 1× 查看实际显示效果
   - 8× 放大检查像素细节
6. **结果**：
   - ✅ 通过 → 保存为 `assets/art/characters/hero/hero_idle_s_00.png`
   - ❌ 未通过 → 保存为 `docs/art/ref/grok/hero_idle_v1_非进仓.png`，迭代修改
